# TTermite versioned App release sources

Each release must have its own exact App version, increasing build number, one reachable commit and complete trilingual notes. These are new current-date reconstruction sources with explicit original-source mapping; the original development branch is preserved. Keep source identity, tests, App version and assets consistent. Never relabel another binary, move remote tags, rewrite original development history, auto-update upstream code, or commit local verification/runtime data. Preserve raw licenses and vendor SSH patches. Credentials belong in Keychain. Correct unpublished reconstruction candidates before fixing a final release source SHA; publish only independently tested sources.

Ship one new feature or one independently tracked problem fix per version. Do not bundle multiple features into a single version. Each version needs its own build, source commit, focused validation and trilingual release notes so regressions can be traced to that change.

In history, explain the change, its observable effect and material limitations together in each item; do not separate existing details from an additional effects section. Classify every item as 新增 / 刪除 / 優化 / 其它 (Added / Removed / Improved / Other), with corresponding item order, category and meaning in Traditional Chinese, Simplified Chinese and English. Preserve source provenance and distinguish planned versions and integration candidates from delivered releases.

For the 2026-10-30 request, original items 1, 2, 3, 5, 6, 7 and 8 must be delivered as seven separate versions; item 4 is cancelled. The unpublished combined 0.6.0 candidate is integration evidence, not an approved seven-feature release. Split actual source changes and independently build and test each version; never relabel the combined binary. Analysis-only or unmet targets must not be presented as completed fixes.

The reconstructed lineage starts at v1.0.0 from the earliest TTermite source. Its history describes every baseline capability, including historical capabilities removed later. Each subsequent commit contains one independently tracked change: added/removed increments minor and resets patch; improved (including bug fixes)/other increments patch. A major added feature that substantially changes architecture increments major and resets minor/patch, with a concrete rationale. All builds increase. Preserve the original development and previous reconstruction refs. Never report planned work, source candidates, or existing binaries as independently validated new releases.
